# Quest Log

A quest log that helps you get organized and gamify your life. You turn your to-dos into quests with importance levels, XP, and levels, so doing the work feels like progress.

It's a quest log first and a game second. The point is to be useful.

## Status

Core quest log works: adding quests, viewing them, and sorting them with an AI helper. The two-column layout is now in: a selectable quest list on the left and a local-model "How to complete this" panel on the right, under a Quests/Daily/Journal/Completed tab bar. A Daily tab holds a per-day scratch task list — add, check off, remove, or Upgrade a task into a full quest through the bottom form. Each quest's tasks are checkable, and a quest can be marked Complete (moving it to the Completed tab, with a Restore option to undo). The Journal tab is a working journal — a textarea and Save button, with entries saved (dated) in localStorage and a "Past entries" list to revisit them. Next up is gamification (XP, levels, rewards) — see Roadmap.

## What it does

Track quests as main or side quests with an importance level (shown as a small red/yellow/green chip) and a category (School, Job, Health, Social, Creative, Career, or Portfolio), plus a task list per quest. The layout is a quest list on the left with the creation form in a fixed bar at the bottom of the page. The form sits on a single row — title, type/category/importance dropdowns, a one-line Tasks field (which grows to about four lines while you're typing) and Add Quest — with the AI Provider settings on a tidy row beneath.

The app sits under a Quests/Daily/Journal/Completed tab bar (OSRS-style beveled tabs). The Journal tab is a working journal: a textarea and a Save button, with entries saved with a date and time in localStorage under `questlog_journal`, and a "Past entries" list (newest first) where clicking an entry loads its text back into the textarea. On the Quests tab, the quest list is selectable — clicking a quest fills the right panel with its title, type, category, and importance plus a "How to complete this" section. That guidance is generated by the local Ollama model (always Ollama, regardless of the settings bar provider) and cached in localStorage per quest, with a Regenerate button to re-run the prompt. The default answer is short (3 sentences or fewer), and a "Think more" button fetches a longer step-by-step plan for the same quest.

The **Daily** tab is a per-day scratch task list: a heading with today's date, a text input with an Add button (pressing Enter also adds), and the day's tasks. Each task has a checkbox (checked tasks get the same line-through and dimmer treatment as quest tasks), a small **Upgrade** button, and a small **Remove** button. Upgrade copies the task text into the quest title field in the bottom bar and switches to the Quests tab with that input focused, so the task can be turned into a full quest with its own type, category, and importance — the daily task itself is left in place. Remove deletes it. Daily tasks are stored per local date (YYYY-MM-DD) in localStorage under `questlog_daily`, separate from the quest data.

Each quest's tasks are checkable — every task has a checkbox, and a checked task is shown with a line-through and dimmer text. Once every task is checked (or if the quest has no tasks), a "Complete quest" button in the right panel becomes enabled. Completing a quest moves it out of the active list and into the **Completed** tab, and clears the selection and panel. The Completed tab lists finished quests (title, type, importance, and completion date, newest first) with a **Restore** button that puts a quest back into the active list with all its tasks unchecked, so an accidental completion can be undone. Completed quests are stored separately in localStorage under `questlog_completed`. (XP and rewards for completing quests are still to come — see Roadmap.)

There's an AI helper for sorting: it suggests an importance (low/medium/high) and type (main/side) for each quest. It works with two providers, switchable in the settings bar:

- **Ollama** — local models at `http://localhost:11434` (default `gpt-oss:20b`)
- **Anthropic** — the Messages API, using a key stored in your browser's localStorage under `anthropicApiKey`

## How to run

Because `index.html` uses ES-module imports, it must be served via HTTP (e.g., with VS Code's Live Server, `python -m http.server`, or any local web server). Opening the file directly with `file://` will block the modules and the UI will not load. This is a browser security restriction, not a bug in the code.

To use the AI helper with Anthropic, set your API key in the browser console: `localStorage.setItem('anthropicApiKey', 'sk-...')`. It's stored only in your browser's localStorage. This is a personal project, so never share your API key. Calling the API from the browser is a convenience, not a secure setup — a small local proxy is the proper option if this ever gets shared.
